# Repeatable Lessons & Mistakes Avoided

- **MISTAKE-001: Treating 0 as falsy (`val || 499`) for prices**:
  - Problem: Setting price to 0 was overwritten by fallback 499 because `0` evaluates to `false` in JS logical OR.
  - Fix: Check `typeof val === 'number' ? val : 499` or `val !== undefined && !isNaN(Number(val))`.
- **MISTAKE-002: Math.max clamping price to minimum 50**:
  - Problem: Inputs clamped with `Math.max(50, ...)` and HTML `min={50}` prevented users from setting prices below 50 or 0.
  - Fix: Use `Math.max(0, ...)` and `min={0}`.
- **MISTAKE-003: Onboarding modal omitting API update**:
  - Problem: Google OAuth onboarding modal updated local Zustand store and socket sync, but never awaited `api.updateUser(...)`, causing backend DB to lose role and price on refresh.
  - Fix: Explicitly call and await `api.updateUser(pendingUser.id, ...)` in `handleOnboardingSubmit`.
- **MISTAKE-004: Direct `prisma.user.delete` failing foreign key constraints**:
  - Problem: Deleting user directly caused Postgres to throw `P2003` foreign key constraint failures due to related sessions, messages, reviews, transactions, userSkills.
  - Fix: Clean up child records inside `prisma.$transaction` before deleting the user.
- **MISTAKE-005: Trusting Client-Provided Pricing or Payee in Payment Endpoints**:
  - Problem: Allowing client payload to supply `amount` or `payeeId` enabled tampering or redirection of transaction funds.
  - Fix: Fetch the session record from the database/in-memory store on the server, enforcing server-stored price and teacher ID. Reject mismatching requests with HTTP 400.
- **MISTAKE-006: Broadcasting Private Booking Creation to All Connected Sockets**:
  - Problem: Emitting `session-request-created` globally exposed private student session booking details to all connected platform users.
  - Fix: Scope notification delivery strictly to the target recipient's personal room (`io.to('user:' + approverId)`).
- **MISTAKE-007: Unrestricted Signaling Event Relay in Live Rooms**:
  - Problem: Attendees could emit `fullscreen`, `workspace`, or state sync events, overriding the teacher/host presentation.
  - Fix: Check contextual room host authorization on all signaling message handlers and reject unauthorized events with `room-error`.
- **MISTAKE-008: Unclosed Sockets, Intervals, or Prisma Connections in Test Teardown**:
  - Problem: Test processes hung or triggered libuv assertion failures (`Assertion failed: req->type == UV_FS`) on exit due to active timers and open socket handles.
  - Fix: Call `server.closeAllConnections()`, await server close callback, disconnect Prisma clients, and mark interval timers with `.unref()`.
- **MISTAKE-009: Allowing Payment Confirmation on Unconfirmed/Pending Sessions**:
  - Problem: Students could submit payment confirmations against sessions that were still awaiting mentor approval.
  - Fix: Verify `session.status === 'confirmed'` before processing payments in `confirm-upi` and `confirm-payment`, returning `400 SESSION_NOT_CONFIRMED` otherwise.
- **MISTAKE-010: Premature Auto-Completion and Auto-Cancellation of Pending Sessions**:
  - Problem: Client `api.getSessions()` converted pending sessions to `completed` if `startTime + duration <= now`, and server cancelled pending requests immediately at `scheduledAt`.
  - Fix: Never auto-complete pending sessions; require explicit teacher action or extended 24h grace period.
- **MISTAKE-011: Hiding Past Pending Sessions in Schedule Tab**:
  - Problem: Schedule filtered pending sessions with `s.status === 'pending' && !isPast`, immediately moving unconfirmed sessions into the Completed tab once their start time passed.
  - Fix: Filter pending tab by `s.status === 'pending'` regardless of time, and only move confirmed sessions to completed.
- **MISTAKE-012: Implicit `.env` Injection by `tsx` During Test Execution**:
  - Problem: Running `npx tsx test/...` from inside `server/` causes `tsx` to automatically inject `server/.env`, inadvertently connecting test suites to the live remote database (where ad-hoc test users do not exist).
  - Fix: Run tests from the project root (where root `.env` lacks `DATABASE_URL`) or explicitly override `DATABASE_URL="" DIRECT_URL=""` for DB-less tests, or point to an explicit local disposable PostgreSQL instance.
- **MISTAKE-013: Dual `DIRECT_URL` and `DATABASE_URL` Precedence in `prisma.config.ts`**:
  - Problem: Overriding only `DATABASE_URL` still allows Prisma CLI v6/v8 to connect to remote Supabase if `DIRECT_URL` is set, because `prisma.config.ts` prioritizes `process.env["DIRECT_URL"] || process.env["DATABASE_URL"]`.
  - Fix: Always override **both** `$env:DATABASE_URL` and `$env:DIRECT_URL` (and `$env:SHADOW_DATABASE_URL`) when directing Prisma to local disposable test databases.
